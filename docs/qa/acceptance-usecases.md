# Hermes-Ma Web GUI 验收用例集（acceptance-usecases.md）

> 生成日期：2026-09-19 · 方法论：use-case-strategist L0-L5 分层（极简/常规/复杂/边界/异常/高风险），从"计划启发"改造为"验收服务"：每条用例均为浏览器黑盒可执行的判定步骤。

## 一、目的

从**单用户真实操作视角**验收 Hermes-Ma（FastAPI + Web UI，本机 AI 智能体工作台）的核心用户旅程与近期改动：uiConfirm 自定义弹窗、设置页统计卡、健康自检字段、Waker「⏰ 调度延迟中」徽章、用量页与 llm_usage 记账、子代理超时默认值等。只判定"用户在界面上能否看到预期结果"，不做代码级检查。

**代码核查备注（2026-09-19，走查当日已更新）**：设置页统计卡（`/api/stats`）、健康自检 name/version/code_dir、Waker overdue 徽章、uiConfirm/红色 toast、「📊 用量」页（导航入口 + `/api/usage` + `static/js/usage.js`）均已确认上线并随 P0 走查通过。UC-L3-02 按 PASS 计。

## 二、执行环境假设

- 服务已本机启动：`python -m web_fastapi.main`，访问 `http://127.0.0.1:8000`（端口以 config.yaml `web_port` 为准）。
- 免认证形态：打开即用，无需登录。
- 中文界面；浏览器窗口宽度 ≥1280px（顶栏徽章、导航文案按宽屏判定）。
- LLM key 已配置且可用 —— **凡标注「LLM 依赖」的用例，若 key 未配置/额度耗尽，记 SKIP**，不得误判 FAIL。
- 数据安全红线（必须遵守）：
  - 涉及**删除/清空/恢复/覆盖**的用例，一律使用用例内临时造的测试数据（标注「临时数据」），**禁止动真实记忆、真实项目、真实会话**。
  - Waker 运行类用例优先用临时新建的低成本 waker（task_prompt 写"直接回复：好的"），减少 LLM 消耗；确需用现有 waker 时先征得用户同意。
  - 修改「设置页」可改项后，用例末尾恢复原值（原值在步骤前先抄录）。

## L0 极简层（冒烟：每页能开、核心元素在）

### UC-L0-01 主页加载与导航可达 · P0
- **目标**：主页（项目空间）可打开，五个导航入口 + 设置入口齐全可点。
- **前置**：服务已启动。
- **步骤**：
  1. 打开 `http://127.0.0.1:8000/`。
  2. 检查顶栏导航：主页 / 对话 / 记忆 / Waker / WakerFlow 五项，右侧 ⚙️ 设置图标。
  3. 依次点击五个导航项再回到主页。
- **预期**：主页出现操作区（💬 直接开聊 / 📂 打开本地目录… / ⬇ 克隆 Git 仓库… / ＋ 新建空间）与「最近打开」区；五个页面均无白屏/报错横幅；导航高亮随页面切换。

### UC-L0-02 对话页核心元素 · P0
- **目标**：对话页加载后输入区、会话侧栏、文件树/Git 面板就位。
- **前置**：同上。
- **步骤**：
  1. 打开 `/chat`。
  2. 观察三栏：左会话侧栏、中输入框（placeholder 含「Enter 发送 / Shift+Enter 换行 / 粘贴·拖拽图片」）、右侧文件树区 + Git 折叠面板。
  3. 观察输入框下工具行：📎、权限模式按钮（🔒 审批）、执行者按钮（🤖 默认助手）、模型按钮（⚙️ 默认）。
- **预期**：三栏结构完整；顶栏右侧出现「📝草稿」会话徽章；无 JS 报错导致的空白区。

### UC-L0-03 记忆页加载 · P1
- **目标**：记忆页三大区块可见。
- **步骤**：打开 `/memory`，检查「🔄 聚合与备份」「📚 记忆列表」「⚠️ 危险操作」三卡。
- **预期**：列表能渲染出条目或空态提示；「🗑️ 清除全部记忆」为红色危险按钮；计数徽章（标题旁 + 「共 N 条」）与列表一致。

### UC-L0-04 Waker 与 WakerFlow 页加载 · P1
- **目标**：两张数字员工管理页可开、列表可渲染。
- **步骤**：分别打开 `/waker`、`/wakerflow`。
- **预期**：Waker 页有「＋ 新建 Waker」按钮和 waker 卡片列表（或空态）；WakerFlow 页有「＋ 新建 Flow」「刷新」「刷新审批」和审批徽章（「审批 0」样式）。

### UC-L0-05 设置页加载与卡片齐全 · P0
- **目标**：设置页全部卡片渲染（近期改动：📊 统计卡、健康自检新字段）。
- **步骤**：打开 `/config`，自上而下核对卡片：🧑 个人偏好 / 🌐 工作区与网络 / 🤖 模型 / ⚙️ 运行参数 / 🧩 子代理与工具 / 📦 模型档案 / 🔧 高级 / MCP 服务 / 健康自检 / 📊 统计。
- **预期**：10 张卡片齐全；「📊 统计」带「只读」徽章且能渲染出数字（会话/LLM 错误/存储行数/数字员工概览），不出现永久「加载中」；「🧩 子代理与工具」中子代理超时（sub_agent_default_timeout）为**只读展示**、显示 500（新默认值）。

## L1 常规层（主流使用路径）

### UC-L1-01 新建空间并进入对话 · P0
- **目标**：从主页新建一个项目空间并切换成功。
- **前置**：主页可开。**临时数据**：空间名 `qa-temp-space`，走查后可留待清理（删除记录用例见 UC-L5-02）。
- **步骤**：
  1. 主页点「＋ 新建空间」→ 弹窗输入名称 `qa-temp-space` → 确定。
  2. 观察最近打开区出现新卡片；按提示或经顶栏项目选择器切入该项目进对话页。
- **预期**：新卡片出现且无报错 toast；进入对话页后右栏文件树显示「当前项目没有文件树」空态（收件箱/未挂载语义）或该新空间空目录，顶栏选择器显示 `qa-temp-space`。

### UC-L1-02 顶栏项目切换器往返 · P1
- **目标**：顶栏下拉切换项目空间并生效。
- **步骤**：
  1. 顶栏项目下拉选择另一已有项目 → 自动跳到对话页。
  2. 再切回 `qa-temp-space`。
- **预期**：每次切换后侧栏会话列表按所选项目过滤；meta/徽章无残留上一项目的会话。

### UC-L1-03 首条消息落库与徽章变化 · P0（LLM 依赖）
- **目标**：草稿会话发首条消息后获得正式 sid，徽章由 📝草稿 变 #sid。
- **前置**：对话页处于草稿态；LLM key 可用。
- **步骤**：
  1. 记录顶栏徽章为「📝草稿」。
  2. 输入「请只回复：收到」回车发送。
  3. 观察徽章、左侧栏会话列表。
- **预期**：用户消息气泡立即出现；回复流式返回「收到」；徽章从「📝草稿」变为「#」开头的会话 id；侧栏出现该会话条目（可重命名）。

### UC-L1-04 流式输出与思维链渐进渲染 · P0（LLM 依赖）
- **目标**：流式输出逐字出现，思维链为可折叠块。
- **前置**：同上，新开草稿。
- **步骤**：
  1. 发送「用 200 字介绍一下你自己的能力」。
  2. 观察回复气泡渲染过程与思维链块。
- **预期**：文字**逐段/逐字增长**（非长时间空白后一次性全出）；思维链（🧠）为可折叠块，默认可展开查看；Markdown（标题/列表/代码块）渲染正常；回复结束后发送键从「停止」同位换回。*重点盯联网调研常见缺陷：回复重复两遍、流中断留半截、自动滚动与用户上滚打架。*

### UC-L1-05 三个选择器切换 · P1（LLM 依赖）
- **目标**：模型 / 权限模式 / 执行者（waker 人格）三个弹出选择器可用且回显。
- **步骤**：
  1. 点权限模式按钮 → 选「⚡ 完全访问」→ 按钮标签与图标变化。
  2. 点执行者按钮 → 若有 waker 人格可选一个；无则确认弹出空列表不报错，保持「默认助手」。
  3. 点模型按钮 → 选一个非默认模型档案（无档案则确认弹层可用）。
  4. 三项切回原值。
- **预期**：每个弹层即点即开、选中项带 ✓；按钮上的 label/图标即时更新；切换过程无 console 报错；发消息不受影响。

### UC-L1-06 记忆手动添加与搜索命中 · P0
- **目标**：手动添加记忆并可被搜索命中（也是后续清空用例的数据来源）。**临时数据**：内容含 `qa-temp` 标记。
- **步骤**：
  1. `/memory` 页在添加输入框输入「qa-temp 测试记忆：用户喜欢蓝色」→ 点「＋ 添加」。
  2. 在搜索框输入 `qa-temp`。
  3. 清空搜索。
- **预期**：添加后 toast「已添加」、列表顶部出现新条目、计数徽章 +1；搜索后列表只剩命中项；清空后恢复全量。

### UC-L1-07 Waker 立即运行与状态流转 · P0（LLM 依赖）
- **目标**：手动触发一次 waker 运行，卡片状态完整走一圈。**临时数据**：新建测试 waker。
- **步骤**：
  1. `/waker` 页点「＋ 新建 Waker」：名称 `qa-temp-waker`、IDENTITY 填「你是测试员工」、task_prompt 填「直接回复：好的」、调度类型「仅手动」、权限模式默认 → 保存。
  2. 在卡片上点「▶ 立即运行」。
  3. 运行期间与结束后观察卡片状态徽章。
- **预期**：运行中按钮变 disabled、状态徽章「▶ 运行中」（蓝）；结束后 last_status 徽章变「ok」（绿）；快速连点「立即运行」不会产生两次并行运行（防双击）。**注意**：手动触发不刷新下次运行时间，属设计行为，不算 FAIL。

### UC-L1-08 Waker 运行历史抽屉与 run 详情 · P1（LLM 依赖）
- **目标**：运行历史抽屉能打开并看到 run 记录与详情。
- **前置**：UC-L1-07 已跑过一次。
- **步骤**：在 `qa-temp-waker` 卡片点「运行记录/历史」入口 → 抽屉打开 → 点列表中这条 run → 查看详情 → 关闭抽屉。
- **预期**：抽屉上半为 run 表（时间/状态等列），能看到刚跑的一条 ok 记录；点开详情能看到本次运行产出（latest_result 内容/Markdown 渲染）；空表时显示「暂无运行记录…」文案。

### UC-L1-09 设置页保存偏好 · P1
- **目标**：「🧑 个人偏好」卡保存后即时生效提示。
- **步骤**：
  1. 打开 `/config`，**先抄录**偏好卡当前值。
  2. 修改一项偏好（如语言风格类文本项）→ 点「保存偏好」。
  3. 观察保存反馈，然后把值改回原值再保存。
- **预期**：保存后出现成功 toast/提示文案（显示 PUT 响应摘要）；页面无刷新重载；恢复原值同样保存成功。

### UC-L1-10 模型档案新增与测试连接 · P1（LLM 依赖：测试要真发请求）
- **目标**：模型档案 CRUD + 「测试」按钮走通。**临时数据**：档案名 `qa-temp-profile`。
- **步骤**：
  1. 「📦 模型档案」卡新增档案 `qa-temp-profile`（填一个真实可用的 base_url/key/model，或抄现有档案参数改名）。
  2. 列表出现新档案 → 点「测试」。
  3. 测试完成后删除该档案（走 uiConfirm）。
- **预期**：新增后列表即时出现；点「测试」按钮进入「测试中…」disabled 态；成功后 toast 显示后端 detail（成功信息）；删除时弹 uiConfirm 确认框，确认后条目消失。

### UC-L1-11 会话重命名 · P1
- **目标**：侧栏会话内联重命名。**临时数据**：用 UC-L1-03 产生的测试会话。
- **步骤**：`/chat` 侧栏对测试会话点 ✏️（或双击会话名）→ 改名 `qa-temp-会话A` → 回车；再按 Esc 重试一次取消路径。
- **预期**：回车后名称即时更新；Esc 取消不保存、恢复原名；失败时出现红色错误 toast。

## L2 复杂层（多依赖组合旅程）

### UC-L2-01 审批卡：变更前审批拦截与放行 · P0（LLM 依赖）
- **目标**：权限模式=变更前审批时，危险操作弹审批卡，批准后继续执行。
- **前置**：LLM key 可用；对话页权限模式为「🔒 变更前审批」；当前项目 `qa-temp-space`。
- **步骤**：
  1. 发送「请在当前工作区创建文件 qa_ok.txt，内容写 QA」。
  2. 观察审批卡出现 → 点「批准」。
  3. 再发一次同类请求，这次点「拒绝」。
- **预期**：步骤 2 出现「🔒 审批」卡（含审批对象与可悬停详情），批准后卡收起、工具面板落一行批准记录、文件写入动作继续；步骤 3 拒绝后助手收到拒绝并回应，不执行写文件；两次决策痕迹都保留在工具面板。**验证文件是否真落盘**可配合 UC-L2-07 文件树刷新查看。

### UC-L2-02 会话侧栏 fork 复制分支 · P1
- **目标**：已有会话可复制出分支并自动切换。**临时数据**：测试会话。
- **步骤**：侧栏测试会话点「⋯」→「📋 复制分支」。
- **预期**：toast 提示「已创建分支（复制 N 条事件），正在切换…」；侧栏出现新会话且当前会话切换为它；两会话名可区分。

### UC-L2-03 事件流对话框 · P2
- **目标**：「⋯」→「📜 事件流」能打开事件查看弹窗。**临时数据**：测试会话。
- **步骤**：对测试会话点「⋯」→「📜 事件流」→ 浏览 → 关闭。
- **预期**：弹窗列出该会话事件（用户消息/助手分段/工具调用等类型可辨）；空会话给空态而非报错；关闭后回到原对话不丢输入框草稿。

### UC-L2-04 按需生成会话总结 · P2（LLM 依赖：10-30 秒）
- **目标**：「⋯」→「📝 生成总结」产出总结入记忆库。**临时数据**：测试会话。
- **步骤**：对测试会话点「⋯」→「📝 生成总结」→ 等待完成提示 → 去 `/memory` 页用来源筛选「会话总结」。
- **预期**：点击后先出现「正在总结」类提示；完成后 toast 回报事实条数；记忆页按来源筛出该总结条目。

### UC-L2-05 图片粘贴上传 · P1（LLM 依赖：需多模态模型才有语义回复）
- **目标**：截图直接粘贴进输入框可上传并随消息发送。
- **步骤**：
  1. 复制任意一张本机图片到剪贴板 → 在输入框 Ctrl+V。
  2. 观察缩略图出现 → 点 📎 按钮再选一张 → 发送消息「这张图里是什么？」。
- **预期**：粘贴与选择两条路径都出现缩略图预览（可移除）；发送后消息气泡带图；模型回复不因图片报错（多模态模型应描述图片；非多模态模型至少不崩、给出可解释回应）。

### UC-L2-06 Todo 小窗 · P2（LLM 依赖）
- **目标**：让助手产生 todo 后小窗出现、可收起/拖动。
- **步骤**：发送「请为'整理季度报告'创建一个三步待办计划并逐条登记 todo」→ 观察 `#todo-panel` → 点 ×收起 → 再让助手更新 todo → 重新出现 → 拖动标题移动 → 双击标题复位。
- **预期**：有 todo 时小窗固定在对话区右上，逐条带状态样式；无 todo 时隐藏；收起后更新会再次唤出；拖动/复位位置变化可见。

### UC-L2-07 文件树与 Git 提交图 · P1
- **目标**：右栏文件树能浏览/刷新，Git 面板显示提交树。**临时数据**：本项目工作区或 `qa-temp-space`（若为 git 仓库）。
- **步骤**：
  1. 选一个挂载了真实目录的项目 → 右栏展开目录节点、点刷新。
  2. 展开 Git 折叠面板 → 查看提交列表 → 试 Pull/Push 按钮（**只看不点**，避免动真实仓库；如需点验证，先确认仓库无未推送内容且用户允许）。
- **预期**：目录树逐级展开、文件名完整不乱码；非 git 工作区显示占位提示而非报错；提交图能渲染出历史提交（hash/信息/时间可辨）。

### UC-L2-08 WakerFlow 手动触发与审批徽章 · P1（LLM 依赖）
- **目标**：编排列表可触发一次运行；审批徽章计数正确。**临时数据**：新建 `qa-temp-flow`（单个 worker 块，prompt「直接回复：flow 完成」）。
- **步骤**：
  1. `/wakerflow` 新建 flow（添加 worker 块）→ 保存。
  2. 列表/卡片上触发运行 → 观察运行中进度行 → 结束后查看运行记录。
  3. 观察页首「审批 N」徽章（本 flow 无 ask_user 块，应保持 0）。
- **预期**：运行中卡片出现进度提示；运行记录抽屉出现一条记录且详情可看；无待审批动作时徽章显示「审批 0」空态样式。（若建含 ask_user 块的 flow，运行后徽章应 +1、点开可审批——可作加测。）

### UC-L2-09 设置页统计卡与真实数据一致 · P0
- **目标**：📊 统计卡数字与系统实际状态对得上（新改动验收）。
- **前置**：已完成 UC-L1-03（产生会话与 LLM 调用）。
- **步骤**：

  2. 去侧栏数一下当前项目会话数、`/waker` 数一下启用数，回来对比。
  3. 刷新 `/config` 再读一次。
- **预期**：卡片各字段有数字（可为 0）而非「—/加载失败」；会话总数 ≥ 侧栏可见会话数；waker 分布的 total/enabled 与 `/waker` 页卡片数一致；刷新后数值单调合理（不凭空清零）。

## L3 边界层（极端条件与边界值）

### UC-L3-01 草稿会话刷新即消散 · P0
- **目标**：未发首条消息的草稿刷新后不残留。
- **步骤**：
  1. `/chat` 新建草稿（侧栏「新建草稿」入口），在输入框打几个字**不发送**。
  2. F5 刷新页面。
- **预期**：刷新后回到草稿态（徽章「📝草稿」），侧栏**没有**多出未命名会话；输入框草稿文字可清空（输入框内容不要求保留）。此前已落库的会话不受影响。

### UC-L3-02 用量页：空态与时间窗 · P1（特性可能未上线 → 见核查备注）
- **目标**：📊 用量页可打开；无数据时空态文案友好；三个时间窗可切换。
- **步骤**：
  1. 从导航/设置寻找「📊 用量」入口（若全站无入口 → 记 BLOCKED）。
  2. 依次切「今天 / 7 天 / 30 天」。
  3. 数据为空时读空态文案；若已有数据（部署后跑过对话/waker），核对汇总卡与明细表分页。
- **预期**：三窗口切换即时生效；空态给出明确文案（如「数据自部署起积累」类提示），不是空白div或报错；有数据时汇总卡、SVG 柱状趋势、明细表分页控件可见可翻。

### UC-L3-03 记忆搜索无匹配空态与来源筛选 · P2
- **目标**：搜索无命中时出现引导性空态。
- **步骤**：`/memory` 搜索框输入 `qa-no-such-keyword-999` → 观察列表 → 切换来源筛选（如「已聚合」）→ 恢复。
- **预期**：无命中显示「没有匹配的记忆——换个关键词，或清空搜索/筛选条件。」而非空白；来源筛选芯片（含统计芯片点击筛选）可用；清空后列表恢复。

### UC-L3-04 清空记忆解锁：输错数字不解锁 · P1
- **目标**：uiConfirm 的 requireText 门禁在输错时保持锁定。**临时数据**：依赖 UC-L1-06 的 `qa-temp` 测试记忆（并确认当前项目绑定记忆条数）。
- **步骤**：
  1. `/memory` 点「🗑️ 清除全部记忆」。
  2. 弹窗中先输入一个**错误**数字（如条数+1）→ 观察确认按钮。
  3. 清空输入 → 观察按钮。
  4. 点「取消/关闭」退出，**不要输入正确数字完成清空**（完整清空流在 UC-L5-01）。
- **预期**：弹窗标题「清空项目记忆」、确认按钮红色且初始禁用；输错数字与空输入时按钮始终禁用；提示文案显示将清除的项目记忆条数与「全局共享记忆不受影响」；取消后记忆列表原样。

### UC-L3-05 输入特殊字符与超长文本 · P2（LLM 依赖）
- **目标**：特殊字符/长文本不破版、不被误吞。
- **步骤**：
  1. 输入框发送含 `<script>alert(1)</script>`、`{{tpl}}`、emoji 🚀、换行的消息（配合一句"原样复述以上内容"）。
  2. 再粘贴一段 5000+ 字长文本发送。
- **预期**：脚本片段作为**文本**渲染不执行（无弹窗）；模板语法原样显示；长文本不撑破气泡布局、可完整发出与回显；发送键状态正常。

### UC-L3-06 Waker「⏰ 调度延迟中」徽章出现与消失 · P2（新改动；数据难自然构造时记 SKIP）
- **目标**：enabled 且 next_run_at 过期超 120s 且未运行时，卡片出现红色徽章。
- **前置**：可临时造一个 waker：调度「间隔执行 1 分钟」+ 过期时间设为约 2 分钟后。
- **步骤**：
  1. 新建 `qa-temp-overdue` waker（如上参数，task_prompt「直接回复：好的」）→ 保存后正常启用。
  2. 等过期时间过后再等 >2 分钟，刷新 `/waker` 列表。
  3. 观察卡片「下次运行」旁徽章；随后停用该 waker 再刷新。
  4. 删除临时 waker。
- **预期**：过期超容差且未在运行时出现红色「⏰ 调度延迟中」徽章（悬停有解释 tooltip）；停用后徽章消失。若调度器正常消化了任务使条件无法满足，记 SKIP 并注明"未能自然构造出 overdue 状态"。

## L4 异常层（失败、中断与恢复）

### UC-L4-01 生成中刷新页面 → 恢复提示条与续流 · P0（LLM 依赖）
- **目标**：刷新后在途生成可恢复，不丢已有内容、不重复生成。
- **步骤**：
  1. 发送一个长回复请求（如「写一篇 800 字的短文」）。
  2. 流式输出进行到一半时 F5 刷新。
  3. 观察恢复提示条与消息区；等待生成结束。
- **预期**：刷新后页面出现「后台生成中/恢复」提示条（或自动接续的事件流），历史用户消息与已落盘助手分段完整重放；生成继续直至 done；**不出现**同一回复重复两份、用户消息丢失或发送键永久锁死。*联网调研高频缺陷点：重连后重复生成、半截消息永久残缺。*

### UC-L4-02 停止生成 · P1（LLM 依赖）
- **目标**：生成中点停止，流即刻终止且 UI 状态复位。
- **步骤**：发送长文请求 → 输出中点原位的「停止」按钮 → 观察气泡与按钮。
- **预期**：流式输出停止；停止键同位换回发送键；已生成部分保留（带中断标识或自然截断）；可立即再次发送新消息。

### UC-L4-03 LLM 调用失败的可见反馈 · P1
- **目标**：模型调用失败时用户能看到明确错误，且统计卡 llm 错误计数可增长。
- **前置**：两条路径任选：A) 有无效 key/过期 key；B) 断网（禁用网络）后发消息。**无 key 且不能断网 → SKIP**。
- **步骤**：
  1. 记录 `/config` 统计卡 llm_errors 当前值。
  2. 用无效凭证（或断网）发送消息 → 观察对话区与 toast。
  3. 恢复网络/凭证，回 `/config` 刷新统计卡。
- **预期**：对话区出现可辨认的错误提示（错误气泡/红色 toast 变体，不是无限转圈）；恢复后统计卡 llm_errors（total 或 last_24h）比步骤 1 增大；后续正常消息可成功。

### UC-L4-04 模型档案测试失败反馈 · P2
- **目标**：测试连接失败时红色 toast 给出后端 detail。**临时数据**：`qa-bad-profile`（base_url 指向 `http://127.0.0.1:9` 这类不通地址）。
- **步骤**：新增该档案 → 点「测试」→ 读 toast → 删除档案。
- **预期**：按钮测试态结束后弹出**红色**错误 toast（error 变体），内容含失败 detail（非裸 "Error"）；删除走 uiConfirm。

### UC-L4-05 切走页面后台生成继续，切回自动接上 · P1（LLM 依赖）
- **目标**：断开 ≠ 停止：去别的页面生成不中断。
- **步骤**：发送长文请求 → 立即切到 `/memory` 停留约 10 秒 → 回 `/chat`。
- **预期**：回到对话页后生成内容已续上（或经恢复提示条接续），最终完整落盘；期间切页无报错 toast；不产生重复回复。

### UC-L4-06 删除当前会话 → 本地换新草稿 · P1
- **目标**：删除正在查看的会话后 UI 平滑落入新草稿。**临时数据**：测试会话（非真实会话！）。
- **步骤**：切换到测试会话 → 侧栏点 🗑 → uiConfirm 弹窗出现 → 确认删除。
- **预期**：删除前弹「确定删除这个会话？不可恢复！」确认框（危险样式）；确认后侧栏条目消失、顶栏徽章回到「📝草稿」、消息区清空为新草稿，**页面不整体刷新**；对真实会话此操作**必须跳过**。

## L5 高风险层（数据安全、注入、暴露面）

### UC-L5-01 清空项目记忆完整解锁流 · P0（用临时记忆！）
- **目标**：输入正确条数才能解锁红色「清空」按钮，清空只影响项目级记忆。
- **前置**：**临时数据**——先用 UC-L1-06 在**当前临时项目**添加 2 条 `qa-temp` 记忆；确认弹窗显示的项目条数与这两条一致。**若当前项目存在真实绑定记忆 → 中止此用例，换临时空间执行或 SKIP**。
- **步骤**：
  1. `/memory` 点「🗑️ 清除全部记忆」→ 弹窗显示「确定清除当前项目的 N 条记忆？」。
  2. 输入框输入与 N 一致的数字 → 确认按钮解锁 → 点「清空」。
  3. 回列表核对；再检查全局共享记忆是否还在。
- **预期**：只有精确输入 N 才解锁；清空后项目绑定记忆归零（列表仅剩全局记忆）、计数徽章同步；全局记忆条目原样保留；toast/列表刷新无报错。

### UC-L5-02 删除项目记录不删磁盘文件 · P0（用临时空间！）
- **目标**：主页删除项目记录只摘记录、不动磁盘。
- **前置**：`qa-temp-space` 已存在；在其工作目录（或 inbox 默认目录）**预先放一个标记文件** `qa_do_not_delete.txt`（若走查代理有文件写权限；无权限则改为核对"记录消失 + 无删除文件提示"）。
- **步骤**：
  1. 主页 `qa-temp-space` 卡片点 ✕ → uiConfirm 弹窗（danger 红按钮、文案含「不会删除磁盘上的任何文件」）→ 确认。
  2. 回主页确认卡片消失；核对标记文件仍在。
- **预期**：删除仅移除记录，卡片从「最近打开」消失；磁盘文件 `qa_do_not_delete.txt` 依然存在；无「已删除文件」类误导 toast（应提示已删除记录）。

### UC-L5-03 删除会话的危险确认拦截 · P1
- **目标**：所有会话删除路径必经 uiConfirm，误触可安全取消。
- **前置**：**临时会话**（UC-L1-03 产生；无则按同法新造）。
- **步骤**：侧栏对临时会话点 🗑 → 先点「取消」→ 核对会话还在 → 再点 🗑 → 确认删除。
- **预期**：取消路径零副作用；确认路径会话消失；真实会话全程未受波及。

### UC-L5-04 记忆内容 XSS 转义 · P2
- **目标**：用户可控的记忆内容在列表中按纯文本渲染。**临时数据**：含标签的记忆，走查后删除。
- **步骤**：添加记忆内容 `<img src=x onerror=alert('qa-xss')>` → 刷新 `/memory` 列表 → 编辑该条再保存 → 最后删除该条。
- **预期**：列表与编辑框中均显示**原文字**，不弹出 alert、不渲染成图片元素（内容已被全字符集转义）；删除走行内 uiConfirm。

### UC-L5-05 Waker 外部 API token 一次性展示与复制 · P2
- **目标**：开启 API 触发的 waker 创建后 token 弹窗可见、可复制，且注意其是否仅在创建时展示。
- **前置**：**临时数据**：新建 `qa-temp-token` waker，勾选「启用外部 API 触发」。
- **步骤**：保存创建 → 观察「🔑 Waker 创建成功」弹窗 → 点「复制」→ 关闭弹窗 → 重新打开该 waker 编辑表单查看 token 是否可见。
- **预期**：创建后弹窗展示 token 并复制成功（toast 反馈）；若设计为仅创建时可见，则后续编辑界面不完整回显明文（或以掩码/重置入口呈现）；走查后删除该 waker。

### UC-L5-06 远程访问暴露面确认 · P2
- **目标**：确认默认仅本机监听；若用户从另一台机器访问过，确认暴露路径是用户主动配置的。
- **步骤**：
  1. 本机访问 `http://127.0.0.1:8000` 正常（已由其他用例覆盖）。
  2. 如走查环境可查启动日志/配置：确认 `web_host` 未被改为 0.0.0.0；若改为非回环，核对启动日志是否打印了「安全警告」横幅。
  3. （可选，用户同意时）从局域网另一设备访问本机 IP:8000，验证与配置一致的可达/不可达。
- **预期**：默认配置下非本机无法访问；一旦绑定非回环地址，启动输出必含显著安全警告（免认证形态下这是唯一防线）；记录实际结论供报告引用。

## 四、走查顺序建议（P0 最短路径，尽量少造数据）

1. **UC-L0-01** 主页冒烟 → **UC-L0-02** 对话页冒烟 → **UC-L0-05** 设置页冒烟（顺带读统计卡基线值，为 UC-L2-09 与 UC-L4-03 留底）。
2. **UC-L1-01** 新建 `qa-temp-space`（唯一必造的项目数据）→ **UC-L1-06** 在该项目添加 2 条 `qa-temp` 记忆（顺带覆盖搜索；同时为 UC-L3-04/UC-L5-01 备好数据）。
3. 回对话页：**UC-L1-03** 发首条消息（草稿→sid、徽章变化）→ **UC-L1-04** 长回复看流式/思维链 → **UC-L2-01** 审批卡（同一会话切权限模式即可）→ **UC-L4-01** 生成中刷新恢复（用长回复，一次发送两用）。
4. **UC-L2-09** 回设置页核对统计卡增量（会话 +N、llm 调用已记账）。
5. **UC-L3-01** 草稿刷新消散（纯刷新，零成本）。
6. Waker 线：**UC-L1-07** 新建 `qa-temp-waker` 并立即运行 →（P1 顺路：UC-L1-08 历史抽屉）。
7. 收尾高危三连：**UC-L3-04** 输错数字不解锁 → **UC-L5-01** 正确条数清空临时记忆 → **UC-L5-02** 删除 `qa-temp-space` 项目记录（核对磁盘文件仍在）。

> 该主链 14 条 P0 全覆盖，仅需造 1 个项目空间 + 2 条记忆 + 1 个测试 waker；LLM 依赖集中在第 3 步与第 6 步，key 不可用时对应记 SKIP 并顺延 P1/P2 用例。
