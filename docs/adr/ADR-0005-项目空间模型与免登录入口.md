# ADR-0005：项目空间模型与免登录入口

- 状态：Accepted（本 ADR 文档集构成 /dev-plan 的输入基线）
- 日期：2026-08-27
- 关联：审计报告 §1（链路）、§2（LOCAL_USER 全局哨兵）、§7；ADR-0003（clone 任务化）、ADR-0004（快照原子化是 project 字段的载体）；产品形态＝已确认的三张草图
- 对应 SLO：A「桌面单机档」——切项目/历史加载 P95 ≤300ms、千文件树渲染 ≤500ms、绑定关系持久

## 背景

产品诉求（已确认）：以「项目空间」为中心重构入口——最近项目卡片 / 新建托管空间 /
打开本地目录 / Git 克隆 / 「直接开聊」收件箱；会话跟随项目；chat 页右侧只读文件树；
登录页与工作区门禁页整体退场。用户已知情选择**彻底移除认证**。

现状事实：

1. **workspace 不是多项目实体**：单一挂载状态机 `MountState(mode: none|local|upload, ...)`
   存 kv scope="workspace" key="mount" 单条 + key="history" 最近 20 条
   （`src/workspace/service.py:35-41, :360-375`）。挂新即顶掉旧，无并存概念。
   工作区页面实为三选一挂载引导页，无文件浏览能力。
2. **登录是无密码门禁而非身份系统**：`POST /api/auth/login` 不校验任何凭据，
   签名 cookie + fork worker（`web_fastapi/routers/auth.py:17-33, :28`）；
   恒返回 LOCAL_USER（`:44-47` 的 me 端点是全站探测点）；HTML 页面壳零鉴权
   （`web_fastapi/routers/pages.py:16-58`）；鉴权完全靠每端点声明 Depends
   （`web_fastapi/dependencies.py:17-30`），无全局中间件。
   main.py 默认绑 127.0.0.1 且非回环打印警告。
3. **前端两道闸门与新模型冲突**：authGuard（`static/js/app.js:8-14`）401 跳 `/`；
   workspaceGate（`app.js:163-180`）在 configured===false 时强跳 /workspace——
   「直接开聊」必须合法化，此门必拆。
4. **硬约束**：`security._DANGEROUS` 封禁冒号/斜杠/前导点（`web_fastapi/security.py:19`）
   → 复合 ID 形态（如 `proj:sess`）在 Web 层一进来就 400；
   user_id 哨兵遍布存储层（目录拼装 `worker_manager.py:284-286` 等）。

## 决策

### D1：projects 实体（新表）

```
projects(slug TEXT PK, name, path, type ∈ hosted|mounted|inbox,
         created_at, last_opened_at)
```

- slug 限 `[a-z0-9][a-z0-9._-]{0,63}`（满足 security 白名单字符域）；
  name 自由文本（中文允许）。重名策略：slug 追加序号 `-2/-3`（/dev-plan 定稿）。
- 内建 inbox 项目（slug 固定 `inbox`, type=inbox）承接「直接开聊」，
  取代 choose_chat_only 门禁语义；无文件根 → 树接口对其返回 404 语义。
- hosted 项目工作区落 `data/projects/spaces/<slug>/`；mounted 引用本地绝对路径
  （沿用现 mount 校验黑名单/拒 symlink 逻辑 `service.py:128-152, :228-232`）。

### D2：会话归属 = 快照 meta 字段 + kv 索引

JSON 快照增加 `"project": "<slug>"` 字段（D1 表为权威源，字段为反规范化缓存）+
kv 索引映射加速列表过滤。`list_sessions(project=?)` 为**可选参数**：
不传=现行为全部返回（旧调用方零改动）。events 表结构与投影函数一字不动
（`derive_messages` 不变量与 13 种 UI 事件 payload 是永不破坏红线）。

### D3：入口页接管 `/`

`/` 从登录页改为欢迎页（草图 1）：最近卡片按 last_opened_at 排序、新建空间、
打开本地目录（目录选择沿用 mounted 流程）、Git 克隆（提交到 RunRegistry 任务，
见 ADR-0003）、右上角常驻「直接开聊」。login.html 删除。
顶栏 userarea 改为当前项目切换下拉（草图 2 📁 ▾）。

### D4：门禁移除

authGuard 删除；workspaceGate 删除，「未配置挂载」成为一切页面的合法停留态；
chat 页徽标显示当前项目名。GET /api/workspace 维持旧形状 `{configured, mode, path,
display_name, mounted_at}` 作为兼容垫片（内部由「当前项目」推导），被锁形状的
`tests/test_web_fastapi/test_workspace_api.py:92` 与前端消费方同时保活。

### D5：auth 层删除

- 移除：login/logout 端点与模板、cookie 签发与校验依赖、WEB_SECRET_KEY 解析器。
- 保留：`GET /api/auth/me` 恒返 `{"user_id":"local"}`（前端多页探测点兼容垫片，
  避免翻动每个页面的启动脚本）；`get_current_user_id` 保留签名、退化为常数函数
  （避免翻动全部路由 Depends）。
- 安全声明（用户已知情确认）：任何能访问端口者等同持有 bash/FS 工具权；
  缓解 = 默认回环绑定与非回环警告**原样保留**。运行约束写入 README/RUNBOOK：
  不要把端口暴露到不可信网络（含 tunnel 场景，或自行加访问令牌再暴露）。

### D6：只读文件树服务

- `GET /api/workspace/tree?project=<slug>&path=<相对路径>`：懒加载逐层展开，
  服务端设限：最大深度、单层条目上限、隐藏文件过滤——防 node_modules 类大目录 DoS
  （SLO：千文件渲染 ≤500ms 是前端预算，服务端条目上限是前提）。
- `GET /api/workspace/tree/preview?...&path=<文件相对路径>`：文本嗅探（二进制拒绝）、
  大小上限截断、UTF-8 解码容错。
- 权限锚点复用 `path_guard.resolve_under_root` 双侧 resolve 包含判定
  （`src/tools/path_guard.py:20-60`）；树根 = 当前项目的 path（hosted/mounted）
  或 mount 兼容层的 current_root。一切写操作仍走对话工具流 + HITL，树只读，
  **不新增人工写通道**。

## 契约影响（集中标注）

**破坏性变更（须同步改测试，禁止静默）**：

| 断言 | 现状 | 变更方向 |
|---|---|---|
| `tests/test_web_fastapi/test_auth.py` | login 任意凭据→cookie+fork worker（:83,:89,:97,:133,:144,:20-36） | 删除 login/logout 用例；me 由「需 cookie」断言改为公开恒返 local |
| `tests/test_web_fastapi/test_security_baseline.py` | WEB_SECRET_KEY 随机生成+告警三条（:54,:63,:75,:84） | 随解析器删除而移除；默认绑 127.0.0.1（:26-33）与非回环警告（:100-113）**保留不动** |
| `test_session_events_api.py` / `test_workspace_api.py` | 未登录 401 用例（:85,:90 / :63） | 反转为匿名 200 形状断言 |
| `/` 路由语义 | 登录页锚点（authGuard 多处跳 `/`） | 欢迎页；相关前端跳转点清理 |

**永不动的红线（再次声明）**：13 种 UI 事件 dict payload 契约、derive_messages 投影
不变量（悬空 tool_call 占位、compact 重建等全套）、fork 三元组响应
`{session_id, event_count, up_to_event_id}`、SSE/NDJSON 编码契约、workspace status 旧形状垫片。

## 备选方案与否决理由

| 候选 | 结论 | 理由 |
|---|---|---|
| 复合 ID `proj:sess` 表达归属 | ✗ | security.py 封冒号，Web 层直接 400；改白名单则打开 NTFS ADS 注入面（Windows 保留字符），得不偿失。 |
| 目录分区存储 `data/sessions/<proj>/…` | ✗ | 动摇 SESSIONS_DIR 与 user_id 目录语义的全部假设链（审计 §2），迁移/回滚成本最高级；meta 字段方案零迁移。 |
| 保留 cookie 自动登录（无感化） | ✗ | 产品永远背着「登录」概念与 secret 生命周期问题（重启全员失效）；与「彻底移除」决议冲突。 |
| MVP 先做 token 访问门 | ✗ | 用户已在问答中明确选择彻底移除；风险接受度已记录在 D5 安全声明。 |
| 文件树支持轻量编辑（REST 直写） | ✗ 本轮否决 | 绕过 HITL 的第二写通道扩大安全面；只读+预览已被用户选定为边界。 |

## 回滚成本

- projects 表与 project 字段均为增量信息：删表/忽略字段即可回到改造前行为——**数据层零不可逆**。
- auth 移除若需回滚要重建 login 端点并改回测试（中等成本，是本 ADR 最大单向门；
  之所以可接受：现状 login 本就无安全价值，重建无身份系统负担）。
- `/` 语义变更回滚 = 还原 pages.py 一处路由 + 模板，低成本。
- 树服务纯新增端点，弃用即消失。

## 验证方式（上线后怎么知道这个决策是对的）

1. 浏览器走查三张草图全流程：欢迎页建空间 → 进 chat 发消息 → 回欢迎页见「刚刚打开」；
   clone 公网仓库 → 卡片出现（失败场景见 ADR-0003 验证 2）；直接开聊进收件箱且右栏隐藏。
2. pytest 重写后全绿，且上表破坏点行数对账（改了哪些断言一条不漏）。
3. 匿名 curl 访问 `/api/sessions`、`/api/chat/stream` 行为正常；`validate_id` 对穿越 ID
   依旧 400（安全校验不随认证一起死）。
4. 性能抽测：≤200 项目数据量下欢迎页首屏 <500ms；千文件目录树展开 <500ms。
