# Hermes-Ma 全流程经验总结

> 2026-09-05 ~ 09-06 · 两轮全库审查 + 六波修复 + 三轮实测驱动的重构
> 从 1269 个测试的基线，走到 1787 passed + 真实浏览器/终端双通道验收
> 本文沉淀可直接复用的方法论与踩过的坑，供后续开发/审查/协作参考

## 一、审查方法论（已被两轮验证有效）

### 1. 分层并行审查 + 独立复核的两段式

```
第一段：按子系统并行 6 路敌意审查（互不知晓彼此发现）
第二段：全部 P1/P2 发现交给"复核组"逐条验证可达性
        → 裁决：确认 / 误报 / 降级 / 升级
```

实测效果：首轮 55 项报告 → 49 确认 + 6 误报剔除。**误报都有价值**——
写进报告的"误报清单"防止后续审查重复报，例如：
- `<select>` innerHTML 注入（in-select 插入模式不执行脚本，仅 UI 破坏）
- Windows 文件名禁 `<>` 使某类路径注入物理不可达
- 有意的 fail-open 设计被误判为缺陷

**关键纪律**：只收"当前出厂配置下可达"的真缺陷；防御纵深建议、
风格意见一律拒收——否则报告会膨胀到无法排期。

### 2. 修复后必须复审修复本身

两轮审查中，**复审组在修复代码里抓到的缺陷不比原始代码少**：

| 修复引入/暴露的问题 | 教训 |
|---|---|
| 并发腿修了、串行腿漏了（todos 丢失） | "同类 siblings"检查：修一个分支时 grep 全部同构分支 |
| 修 A 时把 B 的遮蔽揭开（reject 被静默翻 approve） | 修复的可达面变化要重推 |
| 黑名单从"整体替换"改"追加"，旧配置仍带毒条目 | 配置语义变更要考虑存量用户数据 |
| 测试用桩世界验证了不存在的行为（_Cfg(5) vs 出厂 3） | 测试要读真实出厂配置，别自造世界 |

### 3. 用户实测 > 一切静态分析

本轮最有价值的三个发现全部来自用户实测：
- "只有推理流式、正文弹出" → 定位到 ThinkSplitter PROBE 缓冲（静态审查两轮都没抓到）
- "切回来什么都没有" → 引出整条 SSE 可恢复架构重构
- "记忆模块感觉有问题" → 实测发现检索分数 0.05 vs 阈值 0.4 的刻度失配

**结论：审查收敛后，务必安排真实用户路径的实操验收。**

## 二、架构决策经验

### 1. 多 worker 槽架构的水合责任要闭合

本轮最大的 P0：应用重启后恢复会话发首条消息，新 spawn 的槽 worker
空桶不水合 → 模型失忆 + 轮末覆写快照。根因是"chat 路径与非 chat
路径对同一会话的水合责任从未统一"。

**规则：任何按 session_id 取状态的代码路径，必须走同一个
"取桶或水合"入口**（`_get_or_hydrate_bucket`），禁止各自 `get_bucket`。

### 2. SSE/长连接的三条铁律

1. **消费与请求生命周期解耦**：worker 事件流的后台泵独立于 HTTP
   请求，客户端断开只取消订阅不取消消费（"断开≠取消"）。
2. **可恢复订阅用 GET + EventSource + Last-Event-ID**，补差靠
   per-session 环形缓冲 + 单调 seq；POST 发起流与 GET 订阅流共享
   同一 seq 空间。
3. **重连端点绝不抢生产者锁**（订阅只读缓冲），否则恢复路径会被
   busy 语义打死。

### 3. 类型在 IPC/存储边界会裸奔

`dict[str,str]` 把 `'false'` 字符串灌进只有 yaml 读取路径做类型归一的
settings，导致 `shell_enabled: 'false'` 恒真——**安全开关形同虚设**。

**规则：读（yaml）/写（save）/传（广播）三咽喉共享同一个
`normalize_setting_value`，任何新键入库前先登记类型清单。**

### 4. 流式管线：每一跳对每种数据要对称

正文不流式的根因是 client.py 对 reasoning（直发）与 content（过
ThinkSplitter）处理不对称——拆分器的 PROBE 状态在"永远等不到标签"
的路径上无限缓冲。

**规则：加状态机/缓冲时问一句"如果预期输入永远不来，这个缓冲
何时释放？"**——4000 字符/flush 兜底太粗，应按"信号出现即锁定"。

### 5. 覆盖语义：None=keep 会与"省略键的发送方"组合出残留

模型热切换的三连残留（key/context_window/旧 base_url 串档）都源于
`set_llm_params` 的 None=保持语义遇上只发部分键的调用方。

**规则：状态覆盖接口要么提供显式 clear 通道（clear_model_overrides
+ 四键全量），要么全部发送方强制全键。二选一，别混用。**

### 6. 免认证回环服务的浏览器侧攻击面

"绑定 127.0.0.1"防不住浏览器发起的攻击（CSRF 简单请求、DNS
rebinding）。Host 白名单 + Origin 同源校验两个中间件是最低配置；
sensitive 目录挂载要封子树不是只封根。

## 三、LLM 应用工程经验

### 1. 前端渲染 O(n²) 是流式体验的隐形杀手

每 50ms 对累积全文 marked.parse + DOM 消毒 + innerHTML 全量替换：
短文无感，长文每帧越来越慢形成"人为节流"。修法：块级增量渲染
（已闭合块缓存只追加、仅尾块重渲、围栏感知切分）。
**先修服务端流式再修这个，否则瓶颈只是换了个位置。**

### 2. 检索阈值改刻度要实测校准，不要拍脑袋

混合检索改纯向量后分数分布整体变化，旧 min_score=0.4 把 0.05 分的
正确答案全扔了。修复时用真实库扫描 4 档阈值（0.35/0.40/0.45/0.55），
按"正确答案进 top3 + 每轮存活条数不饥饿"选定 0.40。

**规则：任何打分/阈值常量变更，用生产数据出对照表再定。**

### 3. 记忆/检索的降级判据要看两侧

"查询向量算不出来"才降级关键词 → 文档侧一条向量都没有的库在查询
侧可用时返回恒空（静默全库失明）。降级判据必须覆盖"结构性不可用"
（覆盖率），不只是"本次失败"。

### 4. 安全分类器：首词白名单挡不住参数位展开

`echo $(cmd)`、awk 管道、sed 地址形态、find -fprint0……两轮审查
证明"正则补丁"永远追不上 bash 语义。有效收敛策略：
- 检测到参数位 `$( `` <(` 即 review（不可达语义原则）
- 高危程序（git/sed/awk/find/env）做形态检查器而非黑名单正则
- 黑名单默认表与配置"追加"而非"替换"
- 每条规则配实测样本 + 误杀自查（39 条常规只读命令保持 auto）

## 四、多 Agent 协作工程（并发额度受限场景）

### 1. 文件所有权是并行的生命线

每份任务书显式列出所有权文件 + "禁止碰"清单。**冲突高发文件
（chat.js/config_router.py/worker_process.py）要在任务书里切片**：
"仅 XX 函数区域"。两轮 20+ 并行任务零 merge 冲突。

### 2. 集成缝隙靠"契约前置 + 协调人补线"

并行实现的接缝（前端调用的端点没人实现、A 留的一行接线给 B）：
- 任务书里**写死接口契约**（路径/参数/响应形状），允许并行开发
- 协调人（主 agent）亲自补 ~20 行以内的缝，不值得开任务

### 3. 任务书模板（被验证的结构）

```
背景（根因/用户原话）→ 铁律（禁 commit/禁子 agent/只修清单）
→ 所有权（可改/禁碰）→ 修复清单（每项：位置+现象+修法方向+测试要求）
→ 验证方式 → 输出格式（file:line 摘要/测试名/pytest 原样/关联点）
```

### 4. 被杀任务的处置

额度限制/超时会杀 agent：任务书内容留在对话里，重发即可；
半成品落盘的（文件已改未验证），由协调人接手验证收尾，不回滚。

### 5. 剩余额度的分配纪律

- 修复类任务优先于审查类（用户可感知）
- 用户实测反馈 > 审查发现 > 理论缺陷
- 长任务（>30min）拆阶段，避免整任务报废

## 五、验证体系

### 分层验证清单（每次提交前的完整关卡）

| 层 | 手段 | 说明 |
|---|---|---|
| 单元 | pytest 定向 | 每个修复带回归测试（本轮 1269→1787） |
| 前端 | node --check + vm/DOM 桩 | 前端无测试设施时的最低保障；渲染器/状态机可写 38+55 例桩测 |
| 静态 | grep 自证 | innerHTML 拼接/onclick 拼接/版本号一致性 |
| 集成 | 全量 pytest | conda 环境；并行跑服务时会出资源竞争假失败，单独复跑判定 |
| 实操 | 真实浏览器/终端 | 用户视角场景化验收；安全红线（只批工作区良性写）先写死 |

### 实测采样技巧

- 流式验证：每 2s 采样正文 innerText 长度，看单调增长曲线
- 切页续流：记录离开前长度 → 秒回后首采样应 ≥ 离开值且持续增长
- 判定"修好了"必须有 before/after 对照数字，不凭观感

## 六、遗留事项（下次继续的起点）

1. **非思考模型的正文 PROBE 攒批**：无 reasoning 字段且 content 无
   标签的模型仍会攒到 4000 字符（需 PROBE 短窗口判定信号，有误伤
   内联标签风险）
2. **内联路径 CONTENT 态 flush 丢 ≤6 字符尾巴**（半个标签结尾的边缘态）
3. **todo 手动排序不持久化**（需 worker 写入端点）
4. **`GET /api/sessions/current` 等读路径的伪造 sid spawn 面**
   （PUT 侧已堵，GET 侧未）
5. 记忆库存量孤儿向量 1 条 / 缺 FTS 2 条（一次性清理脚本可解）
6. `docs/ux-audit-cli-2026-09-06.md` 中的 CLI 低优先级项
