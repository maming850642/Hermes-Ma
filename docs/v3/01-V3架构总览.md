```
   │
   ├─ 1. _retrieve_memory()        记忆检索 → yield memory_search
   ├─ 2. _precheck()               token 阈值 → 可能 _compact_messages
   │
   ├─ 3. _react_loop()             ★ 手写 ReAct（while iteration_count < max_iter）
   │     │
   │     ├─ _detect_tool_loop()    重复工具签名检测（防线 2）
   │     ├─ context_manager.build_llm_messages()   窗口截断 + SystemMessage 合并
   │     ├─ mode_guidance 注入     plan/before/full 三模式提示
   │     │
   │     ├─ stream_with_hard_timeout(LLMClient.stream_chat)    ★ 双 deadline
   │     │     ├─ yield token / reasoning_token   流式推送
   │     │     └─ accumulate(chunks) → AIMsg
   │     │
   │     ├─ 无 tool_calls → 剥离 <think> + 存 AIMessage → return（自然终止）
   │     │
   │     └─ 有 tool_calls
   │          ├─ safe_parse_tool_args（容错 JSON）
   │          ├─ registry.process_tool_calls(tool_calls, ctx)
   │          │    ├─ 单工具/含审批 → _execute_serial
   │          │    └─ 多非审批 → _execute_concurrent（ThreadPoolExecutor + copy_context）
   │          │         └─ execute(spec, args, ctx)
   │          │              ├─ coerce_args（轻量类型强转）
   │          │              ├─ decide(spec, args, ctx)  三层权限
   │          │              │    ├─ deny → 返回错误
   │          │              │    ├─ requireApproval → raise InterruptSignal ★
   │          │              │    └─ allow → executor.execute()
   │          │              └─ ToolResult(content, state_updates)
   │          ├─ 合并 state_updates（todos / compact_requested）
   │          └─ continue ReAct
   │
   ├─ except InterruptSignal → _handle_interrupt()
   │     ├─ InterruptSnapshot.create（deepcopy messages + 记录 mode）
   │     ├─ interrupt_store.save(thread_id)

   │
   └─ 4. yield turn_messages + complete
```

### stream_invoke(resume_payload=...) 恢复路径

```
stream_invoke(resume_payload=...)
   │
   └─ _handle_resume(thread_id, resume_payload)
        ├─ snapshot = interrupt_store.pop(thread_id)
        ├─ mode_changed = snapshot.permission_mode_at_interrupt != ctx.permission_mode
        ├─ 重新 decide(spec, pending_args, ctx)
        │     └─ 用户切 full_access → decision.is_allow=True（无需再 approve）
        │
        ├─ allow 路径（is_allow 或 resume_payload=="approve"）
        │     ├─ coerce_args + executor.execute（绕过 decide 避免再次 InterruptSignal）
        │     ├─ ToolMessage(执行结果) 喂回 messages
        │     └─ _react_loop 继续
        │
        └─ reject 路径
              ├─ ToolMessage("命令未获批准") 喂回 messages
              └─ _react_loop 继续（让 LLM 决定下一步）
```

## 1.3 三个关键设计决策（为什么这么设计）

### ① 为什么从 LangGraph 改成手写 ReAct？

> **答**（这是 V3 最核心的决策，背熟）：

- **框架行为和文档不一致**——`langgraph.interrupt()` 在我们用的 0.2.76 版本里，不会向 `stream_mode=["custom","values"]` 的 chunk 注入 `__interrupt__` 键，stream 只是静默结束。结果 HITL 中断检测永远不命中，审批功能完全失效。我们写诊断脚本验证了 0.2.76 的真实行为，最后只能用 `get_state()` 查 checkpoint 绕过——但这是框架黑盒，升级时随时可能再坏。
- **黑盒难调**——LangChain 的 `_create_subset_model` 遇到某些 MCP schema 的 `data` 字段抛 `KeyError`，`bind_tools` 是原子的导致整个 agent 初始化崩溃；`RunnableConfig` 必须手动透传到 `tool.invoke()` 否则 `interrupt()` 读不到 `__pregel_scratchpad`。每一个都要读框架源码才能绕过。
- **依赖太重**——我们实际只用 `langchain_core.messages`（消息类型）+ `convert_to_openai_tool`（schema 转换）+ `parse_partial_json`（容错 JSON）三个函数，却拖进整个 langchain-core / langchain-openai / langgraph 三包。
- **收益**：V3 把这三个函数全部手搓替代，零框架魔法、所有行为可在自己代码里 grep 到、依赖瘦身。代价是 ReAct 循环和 HITL 状态机要自己维护——但这部分逻辑本来就该自己掌控。

### ② 为什么每用户一个 worker 子进程？

- Agent 有大量 **进程级全局状态**：`InterruptStore`（内存快照）、记忆模块的 contextvar（`_current_user_id`）、MCP 客户端的 asyncio event loop 线程、记忆写锁。如果用线程或协程做并发，这些状态的隔离会非常脆弱——早期 V2 就踩过「两个用户信息没隔离、似乎共用一个 LLM 客户端」的坑。
- 子进程是 OS 级隔离，最干净。代价是进程数 = 并发用户数，不适合 C 端百万用户，但对当前 to-B 场景完全够用。
- 生命周期：登录启动 → 登出/应用关闭时销毁。worker 常驻、无定时空闲回收
（2026-08 移除：单用户下回收只有状态重置与总结丢失的副作用）。

### ③ 为什么 Web 进程只做转发、agent 逻辑全在 worker 里？

- 让 FastAPI（异步框架）和 agent（同步阻塞的 `LLMClient` + httpx）**解耦**。FastAPI 永远轻快、只管 HTTP/SSE 协议；agent 的慢调用、线程模型、contextvar 都被封在 worker 进程里，不会拖垮事件循环。
- IPC 用 NDJSON（每行一个 JSON），简单、可调试、天然分帧（`web_fastapi/ipc.py`）。
- FastAPI 的 `/stream` 端点就三行核心代码（`routers/chat.py:34-48`），零 agent 逻辑。

## 1.6 短期 vs 长期记忆（V3 形态）

```
┌─────────────────────────────────────────────────────────────────┐
│                        短期记忆 (Session Memory)                 │
│  存储位置: state["messages"]（V3 用 langchain 消息，混合态）       │
│  CLI持久化: data/sessions/{user_id}/{session_id}.json            │
│  Web持久化: web_fastapi worker SessionBucket → 复用 cli.save      │
│  生命周期: 单次会话                                               │
│  裁剪机制: max_short_term_messages=20（窗口截断 = 40 条）          │
│           + precheck token 阈值（compact_threshold_pct=80%）      │
│           + compact_conversation 工具 / 用户 /compact             │
│  内容:     HumanMessage + AIMessage + ToolMessage + SystemMessage│
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                        长期记忆 (Long-term Memory)               │
│  存储位置: 纯文件 <workspace>/users/<uid>/profile.md (jsonl)      │
│  持久化:   永久（除非用户 /clear）                                │
│  生命周期: 跨会话、跨进程重启                                      │
│  检索机制: 关键词分词匹配（无向量、无 embedding）                   │
│           score = 0.5 + 0.5 * (命中词数 / 查询词数)               │
│  写入双路径:                                                      │
│    主路径: LLM 调 remember 工具 → remember_fact (1 次 LLM: decide) │
│    兜底路径: 会话结束 → Summarizer → extract + decide + upsert   │
│  记忆聚合 Consolidation（详见第 7 章 §7.6）:                       │
│    MemoryConsolidator 把碎片原子记忆喂 LLM 合并去重 → 原地替换     │
│    profile.md；乐观并发（替换前再读追加新增）+ 自动备份可恢复      │
│    MemoryConsolidationScheduler 后台定时触发或 Web 手动触发       │
└─────────────────────────────────────────────────────────────────┘
```

## 1.7 事件协议（从模型到浏览器的完整链路）

```
HermesAgentV3 节点 yield {...}              # V3 直接 yield generator 事件
   ↓
worker._drain_stream_events()                # 转 IPC：make_event(req_id, etype, **data)
   ↓ stdin/stdout NDJSON
FastAPI _ipc_events_to_sse()                 # 转 SSE：encode_sse_event(etype, payload)
   ↓ text/event-stream
浏览器 parseSSE()                            # 按 event:/data: 分帧
```

**事件类型清单**（V3 yield 协议）：

| 事件 | 产生位置 | 含义 |
|---|---|---|
| `token` | `agent_v3.py:400` | LLM 正文增量 token |
| `reasoning_token` | `agent_v3.py:403` | 推理过程（`<think>` 或 vLLM reasoning 字段） |
| `memory_search` | `agent_v3.py:272` | 记忆检索的 query/命中数/hits |
| `tool_start` / `tool_end` | `registry_v3.py:299,318` | 工具开始/结束（带 result） |
| `todos_update` | `registry_v3.py:315` | todos 结构化更新（供前端面板） |
| `auto_compact` | `agent_v3.py:330` | precheck 自动压缩通知 |
| `messages_snapshot` | `agent_v3.py:335` | 压缩后全量快照（绕开增量，内部消化） |
| `human_approval_request` | `agent_v3.py:536` | HITL 审批请求，前端弹批准/拒绝 |
| `complete` | `agent_v3.py:254` | 回合完成 |
| `turn_messages` | `agent_v3.py:248` | **内部事件**，worker 截获回写 session，不转发前端 |

## 1.9 当前未完成（Phase 5-6）

V3 是分阶段迁移，当前停在 Phase 4：

| Phase | 内容 | 状态 |

**混合态消除路径**（Phase 5.5 目标）：

```
当前（Phase 4）              Phase 5.5 目标
─────────────              ──────────────
agent_v3.py                agent_v3.py
  ├─ state["messages"]       ├─ state["messages"]
  │  = langchain 消息  ◄─────┤  │  = AIMsg / HumanMsg / ...（自建）
  │                          │  │
  ├─ _langchain_msg_to_dict  ├─ （删除，直接用 to_dict）
  │  （边界转换）             │
  │                          │
  └─ ContextManager          └─ ContextManager
     用 langchain 消息           改用自建消息类型
```

> **为什么停在混合态？** 分阶段迁移的策略——「只换图引擎，不换业务模块」。一次改太多容易引入难定位的 bug。当前 `HermesAgentV3` 内部 state 仍存 langchain 消息（为 `ContextManager.compact_messages` / `build_llm_messages` 兼容），转换发生在边界：出（`_langchain_msg_to_dict`）把 langchain 消息转 dict 给 `LLMClient`；入（`AIMsg → AIMessage` 重建）把 `LLMClient` 的返回转回 langchain 消息存入 state。
